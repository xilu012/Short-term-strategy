# A 股盘中观察：Windows 试验版

竞价/高开只用于建立候选池。最终信号依赖盘中“拉升 → 缩量回落 → 低点暂稳 → 放量恢复并突破观察期局部高点”。电脑弹窗和响铃，手机看盘、手动下单；没有券商登录或下单功能。

**这是采样和模拟提醒工具，阈值尚未通过真实行情与独立样本验证，不代表已发现高胜率策略。**

## 在 Windows 开始

1. 安装官方 Python **3.11 或以上**，建议 3.12，保留安装器默认的 Tcl/Tk 组件与 Python Launcher。程序只用标准库，无需购买其他软件或安装 pip 包。
2. 下载项目文件，解压至可写文件夹，如 `D:\AShareMonitor`。不要放在只读文件夹。双击 `start_windows.cmd`。
3. 点击“运行合成数据演示”。应依次出现 **观察 → 入场候选 → 失效**，并验证电脑的声音、弹窗能否看到。合成数据和实际行情分别存放。
4. 在界面顶部填写扶摇密钥。密钥只在当前程序内存中使用，不写入配置或日志；退出后需重新输入。也可由安全管理方式注入 `FUYAO_API_KEY` 环境变量。不要把密钥写入启动脚本或分享给他人。
5. 先核对服务商的账户权益与费用，再于 A 股交易时段点击“启动实时监控”。本程序不会购买套餐，但数据调用是否收费以你的账户约定为准，不设想其免费。
6. 先模拟观察并对照手机行情，检查实际时延和漏报，再讨论是否用于实盘。Windows 电源设置中关闭交易时段的自动休眠，保持程序开启、联网、系统时钟准确。关闭窗口即停止，不会在后台常驻。

如果双击失败，在该文件夹终端执行 `py -3 -X utf8 monitor.py` 查看错误。若找不到 `py`，可用 `python -X utf8 monitor.py`。若提示没有 tkinter，使用官方 Python 安装器添加 Tcl/Tk。

## 当前行为

- 动态读取 A 股代码表，限定沪深主板代码，排除名称含 ST/退的股票，以及上市不满 60 自然日或缺少上市日期的股票。这是保守筛选，不能替代交易所逐股交易状态核实。
- 时间统一使用 `UTC+8`，不依赖电脑时区。工作日 09:25–09:30 分批读取竞价终态；只建立观察池，不产生买入信号。晚于 09:30 启动时，通过行情的开盘价识别高开，不能补取过去的完整竞价过程。
- 09:30–11:30、13:00–15:00 滚动扫描全池。涨幅 ≥3% 或高开 ≥2% 的股票进入重点候选，再按当前强度排序，最多重点观察 50 只。非高开股票盘中转强也可进入。
- 默认全池每 2 秒调度一批 100 只，重点池约每 5 秒调度一次；请求串行。**这是目标调度间隔，不是行情更新频率或提醒延迟承诺。** 上游响应、退避和股票池规模都会延长间隔。界面显示实际请求耗时和扫描调度耗时。
- 仅将累计成交量/成交额的增量作为观察依据；不把累计量当作当期量。无更新的重复行情不会确认企稳。超过 90 秒的采样中断或累计量重置，会清除原结构，午休后也重新观察。
- “观察”还不是入场候选。“入场候选”要求回落后的再次放量、反弹幅度和突破条件同时满足；并有冷却、30 秒有效期、涨幅过高过滤及跌破低点/价格偏离失效提醒。
- 启动中跨交易日会停止并要求重启，以重新读取名称和 ST 状态。长时间断网、休眠或服务异常后，不沿用旧观察结构。
- 所有买入提醒都是手动复核的候选，不是成交。观察低点仅代表价格/成交量的间接信号，不代表已经识别真实买盘。

## 默认实验阈值

修改 `config.json` 后重新启动生效，亦可用 `--config custom.json` 覆盖部分配置。

| 条件 | 默认值 |
| --- | --- |
| 过去 180 秒已观察到的上涨 | 至少 1.5% |
| 入场候选当日涨幅 | 3%–9.5%，不在参考涨停价买入 |
| 相对拉升局部高点的回落 | 0.6%–2.5% |
| 回落期间平滑成交速率/拉升阶段平均速率 | 不超过 0.8 |
| 低点未再跌破的观察时间 | 至少 15 秒，且必须有更新的行情 |
| 相对回落低点反弹 | 至少 0.5% |
| 再拉升成交速率/回落期平滑速率 | 至少 1.5 倍 |
| 突破前期观察局部高点的缓冲 | 0.1% |
| 入场信号有效期/同股冷却 | 30 秒/300 秒 |

这些数值用于让第一版行为明确且可复现，不是历史优化结果。当前不区分首板/连板，不包含板块共振、封单或逐笔成交判断；它们需要后续补数据后分别评估。首板与连板股票都可能入池。

## 手动持仓与次日提醒

点击“录入/移除实际持仓”，填写真实代码、均价、股数、买入日期。不会因发出入场候选就假定你买入。买入当日不发卖出提醒；次日起 09:35 后按实验规则检查：

- 相对成本亏损达到 5%；或
- 程序观察到的当日高点盈利至少 1%，随后相对该高点回落 2.5%。

达到参考涨停价时暂不发转弱退出信号；参考价仅为普通主板前收乘 1.1、按分四舍五入，**不是权威涨停价格，也不能确认封板或能否成交**。无主动买盘的涨停、特殊涨跌幅或停牌等情形仍须手机核实。

转弱阈值可调整，无法保证按该价格成交，T+1、跳空、跌停均可能使亏损超过设定值。次日开盘的前 5 分钟当前只观察；持仓提醒是实验规则，不是已验证的最佳卖点。

当日最高价仅记录程序启动后实际观察到的价格，保存在 `data/positions.json`，重启保留同日已记录的高点，但无法补齐关机期间走势。卖出后请及时移除记录。跨日加仓不支持分批可卖数量核算，需要人工判断。录入股票不符合当前股票池时会停止并明确报错，不会静默假装正在监控。

## 数据记录与回放

`data/market.sqlite3` 保存实际行情批次（含接收时间、批次行情时间、请求耗时、股票名称与当时持仓上下文）、信号及运行配置；`data/demo.sqlite3` 单独保存演示。`data/positions.json` 是手动持仓记录。所有这些数据均被 Git 忽略，分享日志前仍应检查个人持仓信息。

```powershell
# 无密钥演示
py -3 -X utf8 monitor.py --demo

# 单次真实行情验证：未注入环境变量时安全提示输入密钥
py -3 -X utf8 monitor.py --probe

# 控制台监控（默认扫描全池）
py -3 -X utf8 monitor.py --live

# 小范围采样：仍会先验证代码表与主板筛选
py -3 -X utf8 monitor.py --live --codes 600000.SH,000001.SZ --max-cycles 10

# 回放自己采集的行情，输出信号数量，不计算交易收益
py -3 -X utf8 monitor.py --replay data/market.sqlite3

# 离线测试，不请求真实接口
py -3 -m unittest -v
```

回放使用接收时刻及当时记录的持仓上下文逐条处理，不使用未来涨停结果筛选信号。当前配置用于回放，历史运行配置另存在 sessions 表中；比较参数时应明确选用配置。

**信号回放不是交易回测**：没有模拟成交、佣金、印花税、滑点或未成交，不输出胜率/收益。后续评估必须保存全部信号和失败样本，计入操作延迟与最小佣金，并使用独立时段检验。SQLite 文件会持续增长，请定期停止程序后备份完整文件、按需归档，不要无限期忽略磁盘占用。

## 已核实的接口与限制

文档来源：[快速开始](https://fuyao.aicubes.cn/docs/quickstart/)、[价格数据](https://fuyao.aicubes.cn/docs/api-reference/prices/)、[竞价数据](https://fuyao.aicubes.cn/docs/api-reference/auction/)、[完整聚合文档](https://fuyao.aicubes.cn/llms-full.txt)。

- Base URL 固定 `https://fuyao.aicubes.cn`，通过 `X-api-key` 请求头鉴权。程序保留 TLS 验证并拒绝重定向，避免密钥被转发到其他站点。
- `/api/meta/tickers/list`：股票代码、名称和上市日期，支持分页。
- `/api/a-share/prices/snapshot`：批量快照。其 timestamp 是**该批次最新**的有效上游时间，不是每只股票的独立时间。程序排除时间未知、最新时间已过旧或明显超前的批次；仍无法证明批内每只股票都新鲜。
- `/api/a-share/auction/snapshot`：最多 100 个代码，`stage=final`。此接口 timestamp 是响应组装时间，不能用它计算竞价数据真实延迟。
- `/api/a-share/prices/historical`：当前只支持日线 `1d`。高频动向/资金流向的分钟指标不等于历史分钟价格，不用它们伪造价格回测。
- 文档说当前不限制累计调用次数，但会动态限流，不等于无限 QPS 或免费。HTTP 429 / `code=4001` 会指数退避到最多 120 秒，避免密集重试；无效密钥 `2001`、权限不足 `2003` 会停止。
- 没有确认固定行情更新频率、批量请求可承受规模、实测市场时延或账户收费。试验应先检查这些条件，必要时降低规模/频率。
- 未接交易日历；周末和午休不请求，节假日依靠快照过旧拦截信号，但仍可能产生无效查询。不能将本机时钟过滤视为完整交易日判断。
- 全池扫描有周期、重点池有容量上限，快速异动可能漏掉；不能宣称全市场每只股票都按 5 秒监控。
